## Developer deviations (judgment)

**D1. Extra `GET /api/attachments/:id`.** Acceptable. It is needed for AC 35 to tell a removed image (`[image removed]`) from another item's image (raw text). It requires a session, returns the same public shape as the list (no `storage_key`), and reveals nothing beyond AC 19, which already lets any signed-in user list any item's attachments. It is not in the spec's API list, so the spec or README should mention it.

**D2. Description read view with an Edit button.** Acceptable, with a note for the owner. AC 34 says the description is rendered "in the dialog's read view", which presupposes one; the old UI only had a textarea. The view does change the existing flow: a saved item now opens read-only and needs an Edit click, and AC 44 says editing is unchanged. The owner should confirm this UX change. It is not blocking because the spec's own wording calls for a read view.

**D3. Async delete route.** Acceptable. The route awaits file removal before it returns 204, so when the response arrives the item's files are gone, which is what AC 21 checks. The row deletion is still one transaction, and a file-removal failure is logged and does not fail the request. File removal happens after commit, so a crash between the two leaves an orphan, which the spec accepts (no background sweep in scope). `deleteIssue` has a single caller (the route).

## Observations (non-blocking)

- **O1. AC 2 and AC 7 conflict on the literal example.** AC 2 says `../../etc/passwd` is "saved and served as a harmless display name", but `passwd` has no allowed extension, so AC 7 correctly returns 415. The safety property (no write outside the files directory) holds. The owner should decide whether the example is meant to be accepted; the spec wording needs a fix either way.
- **O2. Paste counter race (code review, not reproduced).** `pasteUploads` is reset when a dialog opens (`openDescription`, `openDiscussion`). If an upload started in an earlier dialog finishes after the reset, its `setBusy(false)` decrements the counter, which can go negative. Then Save or Post may not be disabled during a later paste. Low impact; worth a small guard.
- **O3.** Text downloads get `; charset=utf-8` appended by Express. Harmless; `nosniff` and the CSP are present.
- **O4.** The 413 message literal `File is too large (max 10 MB).` repeats the limit value in `routes/attachments.js`. AC 6 says the limit must not be repeated elsewhere, but the text is spec-mandated. Deriving the text from the constant would prevent drift.

- **Crash between file write and insert** (orphan). Out of scope per the spec.

- **Login form.** The browser session was created by calling `POST /api/auth/login` from the page. The login form itself was not clicked through.
- **Preview tab content** was checked by the new target URL and by API headers, not by viewing the rendered tab.
- **Real BOE storage backend.** Out of scope (the storage swap is tested with a fake).
- **Lint and typecheck.** Not configured in this repo.
- **Description deletion case for AC 37** (an attachment referenced in the description, then deleted). The same resolver is exercised by the comment case, but this exact path was not run.
