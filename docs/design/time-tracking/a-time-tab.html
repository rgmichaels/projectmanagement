14Does the tab bar have room for a seventh tab?

Spec AC 22; designer input (c)

Current CSS plus Time, typical counts (needs 639px, has 597px: scrolls, Attachments is cut off)

Recommended: tight tabs (7px padding, no gap), typical counts: fits on one row

Recommended, worst-case counts (99, 128, 12, 120.5, 14, 10): scrolls by about 14px

380px wide window: the tab bar scrolls sideways (existing overflow-x: auto)

Measured in headless Edge with the dialog at its usual 660px (597px of tab space after padding), with the system font standing in for Proxima Nova: today's bar with six tabs and typical counts is already 653px wide for an epic and 639px for a work item once Time is added, so it scrolls now. Without count badges it is exactly 597px. The fix is two CSS lines (.tabs.tight in time.css): tab padding 7px and badge margin 4px, which gives 597px (fits, zero spare) for typical counts and 611px for the worst realistic case. The scroll safety net stays, and the script must call scrollIntoView({ inline: "nearest" }) on the selected tab so it is never hidden. Fallbacks if the owner wants more air: widen the dialog from 660px to 720px, or use Option C (Time as a section, no tab).
